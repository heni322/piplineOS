# ADR-0012 — Phase 4: reply handling, data-protection requests, booking and show rate

**Status:** Proposed (recorded at end of Phase 4; engineering decisions taken under the delegation in ADR-0011)

| Decision | Why | Reversible |
|---|---|---|
| **Rules first, model second.** Deterministic multilingual rules (en/fr/de/nl/es/it) detect unsubscribe, objection and data-protection requests before the model runs. The model can *add* a safety class, never remove one. Precedence: data-protection request > objection > unsubscribe | The brief's ≥95% recall target holds even if the model is wrong; proven with a "hostile model" eval that always answers *interested* | — |
| **Two kinds of objection.** An objection *to being contacted* ("stop emailing me") is a safety class (global suppression). A *sales* objection ("we already have a provider") is handled only from the tenant's approved playbook; anything off-playbook goes to a person | Avoids treating "no budget" as a legal objection, and stops the agent improvising answers | Yes |
| **Unsubscribes and marketing objections are recorded as completed data-protection requests, not escalated.** Suppression is applied in the same transaction, which fully actions the right. A legal threat or complaint in the same reply still escalates | The right to object to direct marketing is absolute; an operator task with a 31-day countdown for something already done is noise | Yes |
| **Other data-protection requests (access, erasure, rectification, …) are never answered by the agent.** A response is drafted for a person, the deadline is one calendar month (ICO method: same day next month, else last day of that month), the regime is UK GDPR / EU GDPR / both from the prospect's and company's countries, and an escalation is raised | Legal correspondence must be human-sent; the gateway also refuses to send to a suppressed address | — |
| **Erasure is human-confirmed, MFA-protected, with an identity attestation.** It nulls personal data across prospects, messages, claims, replies, meetings, approvals, logs and AI-call payloads, anonymises a sole-trader company name and moves leads to `erased`. The suppression hash is kept | So the person is never contacted again (permitted retention: the minimum needed to honour the objection) | No (by design) |
| **Logs are redaction-only.** `dry_run_log` and `llm_calls` stay append-only except for setting their encrypted payload columns to NULL (database trigger + column grants) | Erasure must reach logs without making them editable | Yes |
| **Qualification evidence must be verbatim.** A criterion answered from the reply counts only if its quote appears in what the prospect wrote; profile criteria (authority) use the role-relevance score. Incomplete → the agent drafts one qualifying question for approval | Stops a model inventing a reason to book | Yes (min confidence 0.70 configurable) |
| **Slots are computed, not guessed:** host window, both parties' business days and bank holidays, minimum notice, horizon, one slot per day. A taken slot triggers a fresh offer; booking is idempotent per offer and slot and goes through `CalendarGateway` (dry-run writes an ICS to the dry-run log) with a send-stage compliance recheck | No double booking; bookings follow the same three-key rule as email | — |
| **Templated confirmations and reminders go out without per-message approval;** AI-written replies follow the tenant's approval mode | Confirmations and reminders are fixed templates with no model text, and every send still passes the gateway and suppression checks | Yes |
| **AI disclosure "always" by default** ("This reply was drafted with the help of AI."), and always when the prospect asks. The agent may never claim to be human | Honest by default; the earlier wording "checked by our team" was untrue in sampling mode and was removed | Yes (tenant config) |
| **Unsupported language → escalate, never answer.** | The tenant has only approved English copy | Yes |
| **Reschedule links are single-use, signed with a separate HMAC purpose from unsubscribe links,** show only freshly computed slots, and refuse any other time. GET shows a page; POST acts (link scanners prefetch GETs). The form is parsed without adding a multipart dependency | Prevents cross-use of tokens and arbitrary bookings; no new dependency | — |
| **Objection after booking keeps the meeting** (flagged) and skips reminders | The prospect may still attend; we stop marketing contact | Yes (`reminders_after_objection`) |
| **Reschedule limit (default 3) → escalation** | Repeated moves need a person | Yes |
| **Hidden and non-English prompt-injection overrides are removed** (Unicode NFKC, invisible format characters stripped, override patterns in fr/de/nl/es/it) | Found by the extended eval set | — |
