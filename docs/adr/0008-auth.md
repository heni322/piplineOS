# ADR-0008 — Authentication and authorisation

**Status:** Proposed

## Decision
- First-party auth in FastAPI: email + password (Argon2id via `argon2-cffi`), **TOTP MFA mandatory for operators** (`pyotp`), optional for tenant users (recommended).
- Server-side sessions in Postgres; opaque session ID in an `HttpOnly; Secure; SameSite=Lax` cookie; 12h idle / 7d absolute expiry for tenants, 8h absolute for operators; CSRF double-submit token for state-changing requests.
- Roles: `operator`, `tenant_admin`, `tenant_viewer`. Authorisation via explicit permission checks per endpoint (dependency `require(permission)`), mapped from roles in one table, unit-tested as a matrix.
- Login rate-limited (per IP + per account, Valkey counters); lockout with backoff; all auth events in `audit_log` incl. IP country (for the Tunisia access record).
- Invite-only user creation (no self-signup).
- No third-party IdP in MVP (lean budget, fewer sub-processors). OIDC can be added later behind the same session layer.

## Alternatives
Auth0/Clerk (paid at scale, extra US sub-processor), Keycloak (heavy), NextAuth only (would split auth between web and API). Rejected for MVP.
